# Технические требования

Общие ограничения и правила разработки проекта.

---

## 1. Целевые платформы

| Платформа | Приоритет |
|---|---|
| Браузер (WebGL) | Основная |
| Десктоп (мышь + клавиатура) | Поддерживается |
| Мобильный браузер (тач) | Поддерживается |

**Правило:** все системы должны работать в браузере.
**Правило:** UI адаптируется под разрешение и тип управления.

---

## 2. Производительность

| Параметр | Ограничение |
|---|---|
| Целевой FPS | 60 (минимум 30) |
| Врагов на экране | до 300 (мягкий лимит) |
| Сущностей на сцене | до 500 |
| Время кадра | до 16 мс |

**Правило:** любые системы масштабируются под WebGL.
**Правило:** при превышении лимитов — деградация, не краш.

---

## 3. Архитектура

| Термин | Значение |
|---|---|
| Паттерн | Component-Based Architecture (CBA) |
| Данные | ScriptableObject |
| Поведение | MonoBehaviour |
| Связь | IDamageable — контракт урона; IHitHandler — контракт on_hit-модулей |
| Композиция | Контейнер + список модулей |

**Запреты:**
- DOTS, Job System, Burst (не работает в WebGL).
- ECS (не работает в WebGL).
- `async/await`, `Task` (плохо в WebGL).
- `Instantiate` без пула.

---

## 4. Object Pooling

**Обязательно для:**
- Снарядов.
- Взрывов.
- VFX.
- Врагов.

**Правило:** ни один объект не создаётся и не удаляется в `Update` / `FixedUpdate`.
**Правило:** пул предзаполняется при загрузке сцены.

---

## 5. Ограничения VFX

**Правило:** использование визуальных эффектов ограничено из-за WebGL.
**Правило:** приоритет — читаемость, а не зрелищность.
**Правило:** эффекты, влияющие на FPS при массовом использовании, — не добавляются.
**Правило:** количество одновременных VFX — лимитировано.

---

## 6. Сохранение

| Что | Где | Когда |
|---|---|---|
| Прогресс аккаунта | LocalStorage | После раунда |
| Прогресс забега | Не сохраняется | — |

**Правило:** динамическое сохранение невозможно (браузерное ограничение).
**Правило:** сохранение происходит **только** по событию (конец раунда).
**Правило:** при грубом закрытии вкладки — прогресс теряется.

---

## 7. Контент

**Правило:** все параметры контента (модули, турели, шасси, враги, апгрейды) — через ScriptableObject.
**Правило:** добавление нового контента **не требует** изменения кода.
**Правило:** данные отделены от логики.

---

## 8. Локализация

| Язык | Приоритет |
|---|---|
| Русский | Основной |
| Английский | Поддерживается |

**Правило:** все тексты в UI — через систему локализации.
**Правило:** тексты не хардкодятся в скриптах.

---

## 9. Расширяемость

**Правило:** новые модули добавляются без переписывания существующих.
**Правило:** новые турели/шасси/враги — через данные, а не код.
**Правило:** система готова к расширению контента в будущем.
